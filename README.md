# testproject — Планувальник подій (календар)

Веб-додаток, у якому людина може записувати свої події (зустрічі, справи, нагадування)
у календар: додавати, редагувати, видаляти, шукати та фільтрувати за важливістю.
Кожен користувач бачить тільки свої власні події.

## Що планується зробити

- Реєстрація та вхід (email + пароль, а також через Google)
- Календар, де можна натиснути на дату і додати подію
- У події буде: назва, дата й час, опис та важливість (звичайна / важлива / критична)
- Перегляд подій списком, пошук за словом і фільтр за важливістю
- Усі події зберігаються в базі даних

## Технології

| Технологія | Навіщо вона потрібна (простими словами) |
| --- | --- |
| Next.js + TypeScript | Основа сайту: і те, що бачить користувач, і серверна частина |
| Tailwind CSS | Швидке оформлення зовнішнього вигляду |
| shadcn/ui | Готові красиві кнопки, форми, вікна — щоб не малювати їх з нуля |
| lucide-react | Набір іконок |
| Prisma | Зручний спосіб спілкуватися з базою даних із коду |
| PostgreSQL | Сама база даних, де лежать користувачі та їхні події |

## Історія роботи по гілках

Тут після кожної закінченої задачі я дописую, що саме було зроблено.

### Гілка `main` — старт проєкту

Що зроблено:

1. Створено порожню папку проєкту `testproject`.
2. Всередині створено Git-репозиторій — це "журнал змін", який запам'ятовує кожен крок роботи.
3. Створено головну гілку `main`. Гілка — це окрема лінія розробки.
   `main` вважається "чистовиком": сюди потрапляє тільки перевірений результат.
4. Додано цей файл `README.md` з описом проєкту.

### Гілка `dev`

Що зроблено:

1. Від `main` створено гілку `dev` — це "робоча" гілка.
2. Далі кожна нова можливість (авторизація, календар, форма події тощо)
   буде робитися в окремій гілці, яка створюється від `dev`.
   Коли можливість готова — вона вливається назад у `dev`,
   а вже перевірений `dev` періодично вливається в `main`.

Схема простими словами:

```
main   ← чистовик, тут тільки готове
 └── dev   ← сюди збираємо всі нові можливості
      ├── feature/auth       (вхід і реєстрація)
      ├── feature/calendar   (календар)
      └── feature/events     (додавання та редагування подій)
```

### Гілка `feature/setup` — каркас проєкту

Це "фундамент": сам сайт ще майже нічого не вміє, але все, на чому він
будуватиметься, вже стоїть і працює.

Що зроблено:

1. **Створено застосунок Next.js 16** з TypeScript і Tailwind CSS.
   Простими словами: з'явилась програма, яку вже можна запустити в браузері.
2. **Підключено бібліотеку готових компонентів shadcn/ui.**
   Це набір готових кнопок, полів вводу, спливаючих вікон, календаря тощо.
   Їх не треба малювати з нуля — вони одразу гарні й зручні.
   Додано 15 таких компонентів (кнопка, поле, вікно, список, календар та інші).
3. **Підключено іконки lucide-react** — картинки біля тексту (календарик, лупа, зірочка).
4. **Підключено базу даних Neon (Postgres) через Prisma.**
   У файлі `prisma/schema.prisma` описано, які таблиці є в базі.
   Ці таблиці вже реально створені в базі:
   - `User` — користувачі (email, ім'я, зашифрований пароль);
   - `Event` — події (назва, опис, дата й час, важливість, чия це подія).
5. **Зроблено головну сторінку** з назвою проєкту та описом можливостей —
   щоб було видно, що все встановлене справді працює.
6. **Паролі сховано.** Рядок підключення до бази лежить у файлі `.env`,
   який навмисно не потрапляє в git. Замість нього в репозиторії лежить
   `.env.example` — той самий файл, але з порожніми значеннями замість паролів.

Структура папок після цього кроку:

```
testproject/
├── prisma/
│   ├── schema.prisma      ← опис таблиць бази даних
│   └── migrations/        ← історія змін бази
├── src/
│   ├── app/               ← сторінки сайту
│   │   ├── layout.tsx     ← спільна "обгортка" для всіх сторінок
│   │   ├── page.tsx       ← головна сторінка
│   │   └── globals.css    ← загальні стилі
│   ├── components/ui/     ← готові компоненти shadcn/ui
│   ├── lib/prisma.ts      ← підключення до бази даних
│   └── generated/prisma/  ← код, який Prisma створює сама (в git не зберігаємо)
├── .env                   ← справжні паролі (НЕ в git)
├── .env.example           ← зразок без паролів (у git)
└── prisma.config.ts       ← налаштування команд Prisma
```

#### Як запустити проєкт у себе

1. Встановити залежності:

   ```bash
   npm install
   ```

2. Створити файл `.env` на основі зразка і вписати свій рядок підключення до бази:

   ```bash
   cp .env.example .env
   ```

3. Створити таблиці в базі:

   ```bash
   npm run db:migrate
   ```

4. Запустити сайт:

   ```bash
   npm run dev
   ```

   Далі відкрити в браузері http://localhost:3000

#### Корисні команди

| Команда | Що робить |
| --- | --- |
| `npm run dev` | Запускає сайт для розробки |
| `npm run build` | Збирає сайт "начисто", перевіряє помилки |
| `npm run lint` | Перевіряє код на помилки й неохайності |
| `npm run db:migrate` | Оновлює таблиці в базі під поточну схему |
| `npm run db:studio` | Відкриває вікно, де можна подивитись дані в базі очима |
