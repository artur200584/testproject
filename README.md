# testproject — Планувальник подій (календар)

Веб-додаток, у якому людина може записувати свої події (зустрічі, справи, нагадування)
у календар: додавати, редагувати, видаляти, шукати та фільтрувати за важливістю.
Кожен користувач бачить тільки свої власні події.

## Що планується зробити

- Реєстрація та вхід (email + пароль, а також через Google)
- Календар, де можна натиснути на дату і додати подію
- У події буде: назва, дата й час, опис та важливість (звичайна / важлива / критична)
- Перегляд подій списком, пошук за словом і фільтр за важливістю
- Усі події зберігаються в базі даних

## Технології

| Технологія | Навіщо вона потрібна (простими словами) |
| --- | --- |
| Next.js + TypeScript | Основа сайту: і те, що бачить користувач, і серверна частина |
| Tailwind CSS | Швидке оформлення зовнішнього вигляду |
| shadcn/ui | Готові красиві кнопки, форми, вікна — щоб не малювати їх з нуля |
| lucide-react | Набір іконок |
| Prisma | Зручний спосіб спілкуватися з базою даних із коду |
| PostgreSQL | Сама база даних, де лежать користувачі та їхні події |

### Гілка `main` — старт проєкту

Що зроблено:

2. Всередині створено Git-репозиторій — це "журнал змін", який запам'ятовує кожен крок роботи.
3. Створено головну гілку `main`. Гілка — це окрема лінія розробки.

### Гілка `dev`

Що зроблено:

1. Від `main` створено гілку `dev` — це "робоча" гілка.

```
main   ← чистовик, тут тільки готове

      ├── feature/auth       (вхід і реєстрація)
      ├── feature/calendar   (календар)
      └── feature/events     (додавання та редагування подій)
```

#### Як запустити проєкт у себе

1. Встановити залежності:

   ```bash
   npm install
   ```

2. Створити файл `.env` на основі зразка і вписати свій рядок підключення до бази:

   ```bash
   cp .env.example .env
   ```

3. Створити таблиці в базі:

   ```bash
   npm run db:migrate
   ```

4. Запустити сайт:

   ```bash
   npm run dev
   ```

   Далі відкрити в браузері http://localhost:3000

### Гілка `feature/auth` — реєстрація та вхід

Тепер у сайту є "двері з замком": можна створити акаунт, увійти й вийти,
а закриті сторінки чужим не показуються.

Що зроблено:

1. **Реєстрація за email і паролем.** Сторінка `/register`.
   Форма перевіряє, що ім'я не коротше 2 символів, email схожий на email,
   пароль не коротший за 6 символів і що обидва паролі збігаються.
   Якщо щось не так — показує зрозуміле повідомлення українською.
2. **Пароль зберігається безпечно.** У базу йде не сам пароль, а його "хеш" —
   набір символів, з якого пароль назад дістати неможливо.
   Навіть якщо хтось украде базу, паролі він не прочитає.
3. **Вхід.** Сторінка `/login`. Якщо email або пароль неправильні —
   з'явиться напис "Невірний email або пароль".
   Введений email при цьому не стирається, щоб не набирати його знову.
4. **JWT.** Після входу користувач отримує підписаний "квиток" (токен),
   який лежить у нього в браузері. Сервер перевіряє цей квиток на кожній сторінці —
   так він розуміє, хто саме зараз на сайті.
5. **Вихід** — кнопка "Вийти" у шапці сайту.
6. **Закриті сторінки.** Розділ `/calendar` доступний тільки після входу.
   Якщо зайти туди без входу — одразу перекине на сторінку `/login`.
   Перевірка стоїть на сервері, тому "обійти" її через браузер не вийде.
7. **Кнопка "Увійти через Google"** — код готовий. Поки в `.env` немає ключів,
   кнопка показується вимкненою з підказкою (щоб було зрозуміло, чому вона сіра).
8. **Нові таблиці в базі:** `Account`, `Session`, `VerificationToken` —
   вони потрібні бібліотеці входу, щоб зберігати прив'язку до Google.

Нові файли:

```
src/
├── actions/auth.ts             ← серверні дії: реєстрація, вхід, вихід ("use server")
├── lib/
│   ├── auth.ts                 ← налаштування входу (NextAuth)
│   ├── validation.ts           ← правила перевірки форм
│   └── types.ts                ← опис того, що дія повертає у форму
├── components/
│   ├── site-header.tsx         ← шапка з ім'ям користувача і кнопкою "Вийти"
│   └── auth/
│       ├── login-form.tsx      ← форма входу
│       ├── register-form.tsx   ← форма реєстрації
│       ├── google-button.tsx   ← кнопка "Увійти через Google"
│       ├── form-error.tsx      ← червона плашка з помилкою
│       └── submit-button.tsx   ← кнопка з кружечком під час відправки
└── app/
    ├── (auth)/login/page.tsx       ← сторінка входу
    ├── (auth)/register/page.tsx    ← сторінка реєстрації
    ├── calendar/layout.tsx         ← "охоронець": пускає тільки тих, хто увійшов
    ├── calendar/page.tsx           ← поки що заглушка, далі тут буде календар
    └── api/auth/[...nextauth]/route.ts  ← службова адреса для бібліотеки входу
```

#### Як увімкнути вхід через Google

Це робиться один раз і безкоштовно.

1. Зайти на https://console.cloud.google.com/ під своїм Google-акаунтом.
2. Угорі натиснути на список проєктів → **New project**.
   Назвати, наприклад, `testproject`, натиснути **Create**.
3. У пошуку зверху ввести **OAuth consent screen** і відкрити цей розділ.
   - **User Type** → **External** → **Create**
   - Заповнити три обов'язкові поля: назва застосунку (`Планувальник подій`),
     свій email для підтримки і свій email для зв'язку. Решту пропустити (**Save and continue**).
   - У розділі **Test users** натиснути **Add users** і додати свій Google-email —
     інакше Google не пустить вас у власний застосунок, поки він не пройшов перевірку.
4. У пошуку ввести **Credentials** → **Create credentials** → **OAuth client ID**.
   - **Application type**: `Web application`
   - **Name**: будь-яка, наприклад `testproject-local`
   - **Authorized JavaScript origins** → **Add URI**:
     ```
     http://localhost:3000
     ```
   - **Authorized redirect URIs** → **Add URI** (цю адресу треба вписати точно,
     до останнього символу):
     ```
     http://localhost:3000/api/auth/callback/google
     ```
   - **Create**
5. Google покаже вікно з двома значеннями: **Client ID** і **Client secret**.
   Скопіювати їх у свій файл `.env`:

   ```
   AUTH_GOOGLE_ID="сюди Client ID"
   AUTH_GOOGLE_SECRET="сюди Client secret"
   ```

6. Перезапустити сайт (`Ctrl+C` у терміналі, потім знову `npm run dev`).
   Кнопка "Увійти через Google" стане активною.

> Якщо колись виставите сайт в інтернет — треба буде додати ще одну redirect URI
> з реальною адресою, наприклад `https://мій-сайт.com/api/auth/callback/google`.

### Гілка `feature/events` — календар, події, пошук і фільтри

Це вже повноцінний планувальник: подію можна створити, змінити, видалити,
знайти пошуком і відфільтрувати за важливістю.

Що зроблено:

1. **Календар.** Місяць українською, тиждень починається з понеділка.
   Клік по числу показує події саме на цей день.
   Дні, на які вже щось заплановано, **підкреслені** — одразу видно, коли ви зайняті.
2. **Додавання події.** Кнопка "Додати подію" відкриває вікно з полями:
   назва, дата, час, важливість і опис (опис не обов'язковий).
   Дата підставляється та, яку вибрано в календарі — не треба вводити її вручну.
3. **Три рівні важливості:** звичайна (сіра), важлива (жовта), критична (червона).
   Біля кожної події стоїть кольоровий кружечок і підпис.
4. **Редагування.** Олівець біля події відкриває те саме вікно,
   але вже заповнене — міняєте що треба і зберігаєте.
5. **Видалення з підтвердженням.** Кошик питає "Видалити подію?"
   і показує назву, щоб випадково не стерти не те.
6. **Два способи перегляду** (перемикач угорі):
   - **Календар** — календар + події вибраного дня;
   - **Списком** — усі події підряд, від найближчої до найдальшої.
7. **Пошук.** Поле вгорі шукає слово і в назві, і в описі.
   Великі чи малі літери значення не мають.
   Пошук спрацьовує сам через 0,4 секунди після того, як ви перестали друкувати.
8. **Фільтр за важливістю** — випадний список поруч із пошуком.
9. **Пошук і фільтр зберігаються в адресі сторінки**
   (наприклад `/calendar?q=зустріч&importance=CRITICAL`).
   Завдяки цьому таке посилання можна зберегти в закладки або оновити сторінку —
   фільтри не злетять.
10. **Повідомлення.** Після кожної дії внизу з'являється зелена плашка:
    "Подію додано", "Подію оновлено", "Подію видалено".
11. **Якщо форма заповнена неправильно** — показується зрозуміла підказка,
    а введене НЕ стирається.

#### Найважливіше про безпеку

Кожен користувач бачить і змінює тільки свої події. Це зроблено не в браузері,
а на сервері — у кожному запиті до бази стоїть умова "тільки записи цього користувача":

```ts
// видалити можна лише свою подію, навіть якщо підставити чужий id
await prisma.event.deleteMany({ where: { id, userId } });
```

Тому підмінити id чужої події в браузері й видалити її не вийде.

Нові файли:

```
src/
├── actions/events.ts               ← уся робота з базою ("use server"):
│                                     створити, змінити, видалити, знайти
├── lib/
│   ├── importance.ts               ← назви й кольори важливості
│   └── date.ts                     ← перетворення й показ дат українською
├── components/events/
│   ├── calendar-picker.tsx         ← календар із підсвіченими днями
│   ├── event-filters.tsx           ← пошук і фільтр за важливістю
│   ├── event-list.tsx              ← список подій
│   ├── event-dialog.tsx            ← вікно "Нова подія" / "Редагувати подію"
│   ├── event-form.tsx              ← сама форма події
│   └── delete-event-button.tsx     ← кошик із підтвердженням
└── app/calendar/page.tsx           ← сторінка календаря
```

#### Дрібне виправлення

У рядку підключення до бази замінив `sslmode=require` на `sslmode=verify-full` —
бібліотека `pg` показувала через це попередження в консолі. На роботу не впливало,
але тепер консоль чиста.
