# testproject — Планувальник подій (календар)

Веб-додаток, у якому людина може записувати свої події (зустрічі, справи, нагадування)
у календар: додавати, редагувати, видаляти, шукати та фільтрувати за важливістю.
Кожен користувач бачить тільки свої власні події.

## Що планується зробити

- Реєстрація та вхід (email + пароль, а також через Google)
- Календар, де можна натиснути на дату і додати подію
- У події буде: назва, дата й час, опис та важливість (звичайна / важлива / критична)
- Перегляд подій списком, пошук за словом і фільтр за важливістю
- Усі події зберігаються в базі даних

## Технології

| Технологія | Навіщо вона потрібна (простими словами) |
| --- | --- |
| Next.js + TypeScript | Основа сайту: і те, що бачить користувач, і серверна частина |
| Tailwind CSS | Швидке оформлення зовнішнього вигляду |
| shadcn/ui | Готові красиві кнопки, форми, вікна — щоб не малювати їх з нуля |
| lucide-react | Набір іконок |
| Prisma | Зручний спосіб спілкуватися з базою даних із коду |
| PostgreSQL | Сама база даних, де лежать користувачі та їхні події |

## Історія роботи по гілках

Тут після кожної закінченої задачі я дописую, що саме було зроблено.

### Гілка `main` — старт проєкту

Що зроблено:

1. Створено порожню папку проєкту `testproject`.
2. Всередині створено Git-репозиторій — це "журнал змін", який запам'ятовує кожен крок роботи.
3. Створено головну гілку `main`. Гілка — це окрема лінія розробки.
   `main` вважається "чистовиком": сюди потрапляє тільки перевірений результат.
4. Додано цей файл `README.md` з описом проєкту.

### Гілка `dev`

Що зроблено:

1. Від `main` створено гілку `dev` — це "робоча" гілка.
2. Далі кожна нова можливість (авторизація, календар, форма події тощо)
   буде робитися в окремій гілці, яка створюється від `dev`.
   Коли можливість готова — вона вливається назад у `dev`,
   а вже перевірений `dev` періодично вливається в `main`.

Схема простими словами:

```
main   ← чистовик, тут тільки готове
 └── dev   ← сюди збираємо всі нові можливості
      ├── feature/auth       (вхід і реєстрація)
      ├── feature/calendar   (календар)
      └── feature/events     (додавання та редагування подій)
```
